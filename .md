# 🚀 AI Agent ke liye Complete .md Files Guide + Prompts

Bhai, PRD toh ban gaya — bohot accha! Lekin AI agent ko **poora context** chahiye hota hai warna wo har baar confused rahega. Neeche **18 essential .md files** hain jo har serious project mein honi chahiye, aur har ek ke liye **ready-to-use detailed prompt** diya hai.

---

## 📁 Pehle ye Folder Structure banao:

```
📂 project-root/
├── 📄 PRD.md                    ✅ (Already Done) bni nhi h bnani h
├── 📄 PROJECT_CONTEXT.md        ⬜ Master Brain File
├── 📄 ARCHITECTURE.md           ⬜ System Design
├── 📄 TECH_STACK.md             ⬜ Technologies
├── 📄 DATABASE_SCHEMA.md        ⬜ DB Design
├── 📄 API_SPEC.md               ⬜ API Details
├── 📄 FILE_STRUCTURE.md         ⬜ Folder Map
├── 📄 USER_FLOWS.md             ⬜ User Journeys
├── 📄 UI_UX_GUIDELINES.md       ⬜ Design System
├── 📄 AUTH_FLOW.md              ⬜ Authentication
├── 📄 STATE_MANAGEMENT.md       ⬜ State Logic
├── 📄 CODING_STANDARDS.md       ⬜ Code Rules

## 1️⃣ `PROJECT_CONTEXT.md` — 🧠 Master Brain File (SABSE IMPORTANT)

> Ye file agent ka "dimag" hai. Har nayi chat mein ye pehle do.

**📋 Prompt:**
```
Mere project ka PRD.md already bana hua hai. Ab tumhe ek master file 
"PROJECT_CONTEXT.md" banana hai jo AI agent ke liye single source of 
truth hogi.

Is file mein ye sections hone chahiye:

1. **Project Overview** (2-3 lines mein kya hai ye project)
2. **Target Users** (kaun use karega)
3. **Core Problem** (kya problem solve ho rahi hai)
4. **Key Goals** (3-5 bullet points)
5. **Current Phase** (MVP / Beta / Production)
6. **What's Done** (completed features list)
7. **What's Pending** (upcoming features list)
8. **Critical Constraints** (budget, time, tech limitations)
9. **Key Decisions Made** (important architectural/product decisions with reasons)
10. **Glossary** (project-specific terms ka matlab)
11. **Reference Files Map** (baaki .md files kaunsi hain aur kahan hain)

PRD.md ko read karo aur usse extract karke ye file banao. 
Language: Simple English, format: clean markdown.
```

## 2️⃣ `ARCHITECTURE.md` — 🏗️ System Design

**📋 Prompt:**
```
PRD.md ko read karo aur ek detailed "ARCHITECTURE.md" banao jismein:

1. **High-Level Architecture Diagram** (text-based ASCII diagram ya 
   mermaid.js syntax mein)
2. **Architecture Pattern** (Monolith / Microservices / Serverless / 
   Hybrid — with reason WHY)
3. **Frontend Architecture** (Component hierarchy, page routing structure)
4. **Backend Architecture** (Layers: Controller → Service → Repository)
5. **Data Flow Diagram** (User request se response tak data kaise flow karega)
6. **Third-Party Integrations** (Payment, Email, SMS, Maps, etc.)
7. **Caching Strategy** (Redis / CDN / Local)
8. **Scalability Plan** (Abhi kaise chalega, baad mein kaise scale hoga)
9. **Security Layers** (Firewall, Rate Limiting, Input Validation)

Har decision ke saath "WHY" likho taaki agent samjhe ki kyun ye 
choice li gayi.
```

## 3️⃣ `TECH_STACK.md` — ⚙️ Technologies

**📋 Prompt:**
```
PRD.md aur ARCHITECTURE.md ko read karo aur "TECH_STACK.md" banao:

1. **Frontend**
   - Framework (React/Next.js/Vue/etc.) + version
   - Styling (Tailwind/MUI/CSS Modules)
   - State Management (Redux/Zustand/Context)
   - Form Handling (React Hook Form/Formik)
   - HTTP Client (Axios/Fetch)

2. **Backend**
   - Runtime (Node.js/Python/Go)
   - Framework (Express/FastAPI/Django)
   - ORM (Prisma/TypeORM/SQLAlchemy)

3. **Database**
   - Primary DB (PostgreSQL/MongoDB/MySQL)
   - Cache (Redis)
   - Search (Elasticsearch/Meilisearch) — if needed

4. **DevOps & Infra**
   - Hosting (Vercel/AWS/DigitalOcean)
   - CI/CD (GitHub Actions)
   - Containerization (Docker)
   - Monitoring (Sentry/LogRocket)

5. **Third-Party Services**
   - Auth (Firebase/Clerk/Auth0)
   - Payment (Stripe/Razorpay)
   - Storage (S3/Cloudinary)
   - Email (Resend/SendGrid)

Har tech ke saath VERSION NUMBER aur "WHY THIS CHOICE" likho.
```

## 4️⃣ `DATABASE_SCHEMA.md` — 🗄️ Database Design

**📋 Prompt:**
```
PRD.md ko read karo aur "DATABASE_SCHEMA.md" banao jismein:

1. **ER Diagram** (Mermaid.js syntax mein)
2. **Tables/Collections List** with:
   - Table name
   - Columns/Fields (name, type, constraints, default value)
   - Primary Key
   - Foreign Keys & Relationships (1:1, 1:N, M:N)
   - Indexes (kaunse columns pe index hoga aur kyun)
3. **Seed Data** (initial data jo chahiye dev ke liye)
4. **Migration Strategy** (kaise schema changes handle honge)
5. **Soft Delete vs Hard Delete** policy
6. **Data Retention Policy** (purana data kab delete hoga)

Example format:
### Table: users
| Column     | Type         | Constraints          |
|------------|-------------|----------------------|
| id         | UUID        | PK, auto-generated   |
| email      | VARCHAR(255)| UNIQUE, NOT NULL     |
| created_at | TIMESTAMP   | DEFAULT NOW()        |

Saare tables ke liye ye karo based on PRD features.
```

## 5️⃣ `API_SPEC.md` — 🔌 API Documentation

**📋 Prompt:**
```
PRD.md aur DATABASE_SCHEMA.md ko read karo aur "API_SPEC.md" banao:

1. **Base URL** (dev, staging, prod)
2. **Authentication Method** (JWT / Session / OAuth)
3. **Common Headers** (Content-Type, Authorization, etc.)
4. **Response Format** (standard JSON structure)
5. **Error Response Format** (standard error structure)

6. **API Endpoints** — Har endpoint ke liye:
   - Method (GET/POST/PUT/DELETE/PATCH)
   - Path (/api/v1/users)
   - Description
   - Request Body (JSON example)
   - Query Params (if any)
   - Response (success + error examples with status codes)
   - Auth Required? (Yes/No + Role)
   - Rate Limit

Group endpoints by module:
- Auth APIs
- User APIs
- [Feature] APIs
- Admin APIs

RESTful naming conventions follow karo.
```

## 6️⃣ `FILE_STRUCTURE.md` — 📂 Folder Map

**📋 Prompt:**
```
TECH_STACK.md aur ARCHITECTURE.md ko read karo aur "FILE_STRUCTURE.md" 
banao jismein:

1. **Complete folder tree** (har file aur folder ka naam)
2. **Har folder ka purpose** (1 line description)
3. **Naming conventions** (files kaise name hongi — kebab-case, 
   camelCase, PascalCase)
4. **Har major file ka responsibility**

Example:
```
src/
├── app/                    # Next.js App Router pages
│   ├── (auth)/             # Auth group routes
│   │   ├── login/
│   │   └── register/
│   ├── (dashboard)/        # Protected routes
│   └── layout.tsx          # Root layout
├── components/
│   ├── ui/                 # Reusable UI (Button, Input)
│   ├── forms/              # Form components
│   └── layout/             # Navbar, Sidebar, Footer
├── lib/                    # Utilities & helpers
├── services/               # API call functions
├── hooks/                  # Custom React hooks
├── store/                  # State management
├── types/                  # TypeScript interfaces
└── styles/                 # Global styles
```

Ye actual project ke hisaab se customize karo.
```

## 7️⃣ `USER_FLOWS.md` — 🚶 User Journeys

**📋 Prompt:**
```
PRD.md ko read karo aur "USER_FLOWS.md" banao jismein:

1. **User Personas** (2-3 types ke users — e.g., Admin, Regular User, Guest)

2. **Har persona ke liye complete user flows:**
   - Flow ka naam
   - Step-by-step journey (numbered)
   - Har step pe: User kya karta hai → System kya karta hai → 
     Kahan redirect hota hai
   - Edge cases (kya hoga agar error aaye, kya hoga agar data na ho)
   - Success state & Failure state

3. **Critical Flows jo detail mein chahiye:**
   - Onboarding / Sign Up Flow
   - Login Flow (including forgot password)
   - Core Feature Flow (project ka main kaam)
   - Payment Flow (if applicable)
   - Profile/Settings Flow

Mermaid.js flowchart syntax mein bhi dikhao har flow ko.
```

## 8️⃣ `UI_UX_GUIDELINES.md` — 🎨 Design System

**📋 Prompt:**
```
PRD.md ko read karo aur "UI_UX_GUIDELINES.md" banao jismein:

1. **Design Philosophy** (Minimal? Bold? Corporate? Playful?)
2. **Color Palette**
   - Primary, Secondary, Accent
   - Success, Warning, Error, Info
   - Background, Surface, Text colors
   - (Hex codes ke saath)
3. **Typography**
   - Font Family (heading + body)
   - Font Sizes (h1-h6, body, caption)
   - Font Weights
4. **Spacing System** (4px grid? 8px grid?)
5. **Border Radius** (buttons, cards, modals)
6. **Shadows** (elevation levels)
7. **Component Library** (kaunse pre-built components use honge)
8. **Responsive Breakpoints** (mobile, tablet, desktop widths)
9. **Dark Mode** (Yes/No, agar haan toh color mapping)
10. **Icon Set** (Lucide / Heroicons / Phosphor)
11. **Animation Guidelines** (transitions, hover effects)
12. **Accessibility** (contrast ratio, keyboard nav, ARIA)

Tailwind config ke format mein bhi de do colors agar Tailwind use ho raha hai.
```

## 9️⃣ `AUTH_FLOW.md` — 🔐 Authentication & Authorization

**📋 Prompt:**
```
PRD.md aur TECH_STACK.md ko read karo aur "AUTH_FLOW.md" banao:

1. **Auth Method** (Email+Password / OTP / OAuth / Magic Link)
2. **Auth Provider** (Custom JWT / NextAuth / Clerk / Firebase)
3. **Token Strategy**
   - Access Token (expiry, storage location)
   - Refresh Token (expiry, rotation policy)
4. **Session Management** (kaise handle hoga)
5. **Role-Based Access Control (RBAC)**
   - Roles list (Admin, User, Moderator, etc.)
   - Har role ko kya access milta hai
   - Route protection strategy
6. **Complete Flows:**
   - Sign Up (with email verification?)
   - Login
   - Logout
   - Forgot Password
   - Reset Password
   - Social Login (Google, GitHub, etc.)
7. **Security Measures**
   - Password hashing (bcrypt/argon2)
   - Brute force protection
   - CSRF protection
   - CORS policy
8. **Middleware Logic** (kaunse routes protected hain)
```

## 🔟 `STATE_MANAGEMENT.md` — 🔄 State Logic

**📋 Prompt:**
```
PRD.md, TECH_STACK.md aur ARCHITECTURE.md ko read karo aur 
"STATE_MANAGEMENT.md" banao:

1. **State Types**
   - Server State (API se aaya data — React Query/SWR?)
   - Client/Global State (UI state — Zustand/Redux/Context?)
   - Local State (component-level — useState)
   - URL State (search params, filters)
   - Form State (React Hook Form)

2. **Global Store Structure** (store ka shape dikhao)
   Example:
   ```
   {
     user: { profile, preferences, isAuthenticated },
     ui: { sidebarOpen, theme, modal },
     cart: { items, total, discount }
   }
   ```

3. **Data Fetching Strategy**
   - Kab fetch hoga? (on mount, on demand, polling)
   - Caching policy
   - Optimistic updates (kahan use honge)
   - Error retry logic

4. **State Flow Diagrams** (critical features ke liye)
5. **When to use what** (guidelines for agent)
```

## 1️⃣1️⃣ `CODING_STANDARDS.md` — 📏 Code Rules

**📋 Prompt:**
```
TECH_STACK.md ko read karo aur "CODING_STANDARDS.md" banao jo AI agent 
ko batayega ki code kaise likhna hai:

1. **Language & Version** (TypeScript 5.x, Python 3.12, etc.)
2. **Strict Mode** (TypeScript strict: true?)
3. **Naming Conventions**
   - Variables: camelCase
   - Components: PascalCase
   - Files: kebab-case
   - Constants: UPPER_SNAKE_CASE
   - DB tables: snake_case
4. **Code Organization Rules**
   - Max file length (e.g., 300 lines)
   - Max function length (e.g., 50 lines)
   - Single Responsibility Principle
5. **Import Order** (external → internal → styles)
6. **Error Handling Pattern** (try-catch, custom error classes)
7. **Commenting Rules** (kab comment karna hai, kab nahi)
8. **Git Commit Convention** (Conventional Commits: feat:, fix:, etc.)
9. **ESLint / Prettier Config** (key rules)
10. **DO's and DON'Ts** (10-15 important rules)
    - ✅ DO: Use early returns
    - ❌ DON'T: Use any type in TypeScript
    - ✅ DO: Extract magic numbers to constants
    - ❌ DON'T: Nest more than 3 levels
```

## 1️⃣6️⃣ `ERROR_HANDLING.md` — ⚠️ Error Patterns

**📋 Prompt:**
```
ARCHITECTURE.md aur API_SPEC.md ko read karo aur "ERROR_HANDLING.md" banao:

1. **Error Categories**
   - Client Errors (400s — validation, bad input)
   - Server Errors (500s — DB fail, timeout)
   - Auth Errors (401, 403)
   - Network Errors (offline, timeout)
2. **Standard Error Response Format**
   ```json
   {
     "success": false,
     "error": {
       "code": "VALIDATION_ERROR",
       "message": "Email is required",
       "details": [...]
     }
   }
   ```
3. **Custom Error Classes** (AppError, ValidationError, NotFoundError)
4. **Global Error Handler** (middleware logic)
5. **Frontend Error Handling**
   - Error Boundaries
   - Toast notifications
   - Fallback UI
6. **Logging Strategy** (kya log karna hai, kahan)
7. **User-Friendly Error Messages** mapping
```

## 💡 Pro Tips:

| Tip | Detail |
|-----|--------|
| 🔄 **Har nayi chat mein** | `PROJECT_CONTEXT.md` + `CODING_STANDARDS.md` pehle do |
